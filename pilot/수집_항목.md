# 어떤 기록을 남기는가

코드에서 뽑아낸 전체 목록이다. 모든 기록에는 누가(계정), 언제(시각)가 함께 붙는다.
개인을 알아볼 수 있는 값(이메일, 이름, 연락처)은 어디에도 넣지 않는다.
GA에는 참가자 번호만 보내고 이메일은 보내지 않는다.

## 1. 택 인식

| 기록 | 언제 | 함께 남는 값 |
|---|---|---|
| `ocr_called` | 서버가 구글 비전을 부를 때 (서버에서 남김) | 사진 용량 |
| `ocr_done` | 인식이 끝났을 때 | 걸린 시간(초), 사용한 엔진, 읽어낸 글자 수, 브랜드·가격·사이즈·소재를 각각 찾았는지 |
| `ocr_failed` | 인식이 실패했을 때 | 실패 사유 |
| `gallery_opened` | 갤러리에서 사진을 고를 때 | 촬영 모드 |

인식 정확도는 `ocr_done`의 `found_*` 값과 아래 `item_updated`를 같이 보면 나온다.
자동으로 채웠는지(found), 채웠는데 틀려서 고쳤는지(updated)가 구분된다.

## 2. 상품 저장과 수정

| 기록 | 언제 | 함께 남는 값 |
|---|---|---|
| `item_saved` | 상품을 저장했을 때 | 브랜드, 카테고리, 가격, 사진 수, 소재·세탁법이 채워졌는지 |
| `item_updated` | 저장한 내용을 고쳤을 때 | 고친 항목 이름들 |
| `item_deleted` | 상품을 지웠을 때 | 브랜드 |
| `all_data_cleared` | 전체 삭제를 눌렀을 때 | 지운 상품 수 |
| `item_shared` | 공유를 눌렀을 때 | 브랜드, 사진을 함께 보냈는지 |

## 3. 비교와 결정 (핵심 지표)

| 기록 | 언제 | 함께 남는 값 |
|---|---|---|
| `compare_list_opened` | 찜 목록을 열었을 때 | 그 시점 찜한 개수 |
| `compare_run` | 한눈에 비교를 실행했을 때 | 비교한 상품 수, 브랜드 목록 |
| `decision_made` | 샀어요·보류·안 사기로를 눌렀을 때 | 무엇을 골랐는지, 이전 결정, 어느 화면에서 눌렀는지, 비교를 거쳤는지, 비교 횟수, 저장 후 몇 분 만인지, 가격, 브랜드 |
| `decision_cleared` | 결정을 취소했을 때 | 위와 같음 |
| `auto_held` | 하나를 고르면서 나머지가 보류로 넘어갔을 때 | 넘어간 개수 |

`decision_made`의 `compared_before`와 `source`가 "비교 기능이 결정을 도왔는가"의 직접 근거가 된다.

## 4. 구매 판단을 돕는 기능

| 기록 | 언제 | 함께 남는 값 |
|---|---|---|
| `duplicate_warned` | 옷장에 비슷한 옷이 있다고 알렸을 때 | 닮은 정도(%), 두 상품의 브랜드 |
| `duplicate_opened` | 그 경고를 눌러 비슷한 옷을 열었을 때 | 없음 |
| `hold_reminder_shown` | 오래 보류한 옷을 다시 보여줬을 때 | 며칠 지났는지, 몇 벌인지 |
| `hold_reminder_opened` | 그 안내를 눌렀을 때 | 위와 같음 |
| `price_search_opened` | 가격 검색을 눌렀을 때 | 브랜드, 어디서 검색했는지(무신사·구글·네이버) |
| `price_ask_shown` | 검색하고 돌아와 가격을 물어봤을 때 | 없음 |
| `online_price_entered` | 온라인 가격을 적었을 때 | 매장가, 온라인가, 차액, 브랜드 |

`price_ask_shown` 대비 `online_price_entered` 비율이 "직접 적게 하는 방식이 쓸 만한가"의 답이 된다.

## 5. 계정과 화면

| 기록 | 언제 | 함께 남는 값 |
|---|---|---|
| `signed_up` / `signed_in` / `signed_out` | 가입, 로그인, 로그아웃 | 없음 |
| `screen_view` | 화면을 옮길 때 | 화면 이름 (GA에만 보낸다) |
| `offline_start` | 서버에 닿지 못한 채 시작했을 때 | 없음 |

## 6. 문제 추적 (분석용이 아니라 고장을 찾기 위한 기록)

| 기록 | 언제 | 함께 남는 값 |
|---|---|---|
| `js_error` | 앱에서 오류가 났을 때 | 오류 메시지, 발생 위치, 그때 보던 화면 |
| `photo_store_failed` | 사진 저장에 실패했을 때 | 오류 이름, 사유 |
| `photo_store_unavailable` | 기기가 사진 저장을 아예 못 할 때 | 오류 이름, 사유, 홈 화면 실행 여부 |
| `storage_failed` | 기기 저장에 실패했을 때 | 용량 초과인지, 사유, 상품 수 |
| `sync_failed` | 동기화에 실패했을 때 | 사유 |
| `account_switch_clear_failed` | 계정이 바뀌었는데 앞 사람 자료를 못 지웠을 때 | 사유 |

이 기록들은 참가자가 제보하지 않아도 문제를 알아채기 위한 것이다.
실제로 P05의 저장 실패 원인을 여기서 찾았다.

## 어디에 쌓이는가

두 곳에 같은 기록을 남긴다.

- **Supabase**: 발표에 넣을 숫자는 여기서 뽑는다. 유실이 없고 SQL로 정확히 계산된다
- **GA4**: 흐름을 훑어보는 용도. 세션, 유지율, 기기 종류는 GA가 자동으로 계산해 준다

`screen_view`는 자주 발생해서 GA에만 보낸다. 서버 요청을 줄이기 위해서다.
