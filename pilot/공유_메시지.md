# 팀 공유용 카톡 메시지

파일럿 테스트 준비 상황을 팀에 알릴 때 쓰는 메시지.

---

파일럿 테스트 준비 끝났습니다. 정리해서 공유드립니다.

**흐름**

참가자가 주소 열어서 홈 화면에 추가하면 앱처럼 씁니다. 회원가입할 때 데이터 수집 동의를 받고, 참가자 번호를 입력받아서 누가 누군지 구분합니다.

쓰는 건 이렇습니다. 옷 가게에서 태그를 찍으면 서버가 구글 비전으로 글자를 읽어서 브랜드, 가격, 사이즈, 소재, 세탁법을 자동으로 채웁니다. 틀린 게 있으면 참가자가 직접 고칩니다. 마음에 드는 걸 찜해두고, 두 벌 이상 모이면 나란히 놓고 비교합니다. 비교 화면에서 바로 샀어요, 보류, 안 사기로 중에 고르면 결정이 기록됩니다.

저장한 내용은 서버에 올라가서 휴대폰이랑 컴퓨터 어디서 열어도 이어서 볼 수 있습니다. 사진도 같이 올라갑니다.

**연결한 것**

Supabase로 로그인, 데이터베이스, 사진 저장, OCR 서버 대행을 처리합니다. 접근 권한은 본인 데이터만 보이게 막아뒀습니다. 다른 참가자 옷이나 사진은 안 보입니다.

구글 비전 API 키는 서버에만 두고 앱에는 안 넣었습니다. 참가자가 각자 키를 넣을 필요도 없고 키가 새지도 않습니다. 비용 때문에 1인당 하루 20장으로 제한했습니다.

GA4를 붙여서 사용 기록을 남깁니다. 같은 기록을 Supabase에도 남겨서, GA는 흐름을 훑어보는 용도로 쓰고 발표에 넣을 숫자는 Supabase에서 뽑습니다.

**어떤 로그를 남기나**

인식 쪽
- 태그를 찍고 인식이 끝날 때마다 걸린 시간, 항목별로 자동으로 채워졌는지 여부
- 참가자가 나중에 고친 항목이 무엇인지
- 인식이 실패하면 실패 사유

이 둘을 같이 보면 "채웠는데 틀림"과 "아예 못 채움"을 나눌 수 있습니다. 개발 세트 135장으로 잰 정확도 말고 참가자가 실제로 찍은 태그 기준 숫자가 나옵니다.

의사결정 쪽
- 찜 목록을 열었는지, 실제 비교까지 갔는지
- 비교할 때 몇 벌을 놓고 했는지
- 결정할 때 그 상품이 비교를 거쳤는지, 저장하고 결정까지 몇 분 걸렸는지, 비교 화면에서 눌렀는지 상세 화면에서 눌렀는지
- 마음을 바꾼 경우 이전 결정이 뭐였는지

핵심은 비교를 거친 상품과 아닌 상품의 결정률 차이입니다. 이게 "비교 기능이 의사결정을 도왔다"는 주장의 근거가 됩니다.

운영 쪽
- 앱에서 오류가 나면 오류 내용과 그때 보던 화면
- 동기화나 저장이 실패하면 그 사실

참가자 휴대폰에서 문제가 생겨도 제보를 기다리지 않고 알 수 있게 해뒀습니다.

**분석 쿼리**

인식 정확도, 비교 효과, 참가자별 현황을 뽑는 쿼리를 미리 써뒀습니다. 파일럿 끝나면 바로 돌리면 됩니다.

**남은 일**

참가자 10명 모집, 2주 진행, 끝나고 설문입니다. 안내문도 써뒀습니다.
